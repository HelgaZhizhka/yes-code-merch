# React Rules for AI Assistants

## General Principles

### Functional Components Only
Always use **Arrow Functions** for components, hooks, and all internal logic. 

```typescript
// ✅ Good - Explicitly typed arrow function
export const ProductCard = ({ product }: { product: Product }): JSX.Element => {
  return (
    <div className="card">
      <h3>{product.name}</h3>
      <p>{product.price}</p>
    </div>
  );
};

// ❌ Bad - NEVER use class components
class ProductCard extends React.Component {
  render() {
    return <div>...</div>;
  }
}

// ❌ Bad - Avoid the 'function' keyword
export function ProductCard(props) { ... }
```

> **Exception:** `src/shared/ui/` components generated by **shadcn/ui** use the `function` keyword by default. Do NOT refactor these — it's the expected shadcn output pattern. New custom components outside of `shared/ui/` must still use arrow functions.

### Hooks Rules

1. Call hooks only at the **Top Level**.
2. Call hooks only within **React functions** (Components or Custom Hooks).
3. Custom hooks must always start with the **`use`** prefix.

```typescript
// ✅ Good
const MyComponent = () => {
  const [count, setCount] = useState<number>(0);
  const value = useMemo(() => expensiveCalc(), []);
  
  return <div>{count}</div>;
};

// ❌ Bad - Hooks inside conditions/loops
const MyComponent = () => {
  if (condition) {
    const [count, setCount] = useState(0); // ERROR!
  }
  return <div>...</div>;
};
```

## State Management

### useState

```typescript
// ✅ Good - Simple typed state
const [count, setCount] = useState<number>(0);
const [user, setUser] = useState<User | null>(null);

// ✅ Good - Functional updates
setCount(prev => prev + 1);
setItems(prev => [...prev, newItem]);

// ❌ Bad - Direct state mutation
items.push(newItem); // NEVER do this!
setItems(items); // Will not trigger re-render!

// ✅ Good - Immutable updates
setItems([...items, newItem]);
```

### Derived State

```typescript
// ✅ Good - Calculate during render
const ProductList = ({ products }: { products: Product[] }) => {
  const inStockProducts = products.filter(p => p.inStock);
  const totalPrice = products.reduce((sum, p) => sum + p.price, 0);
  
  return (
    <div>
      <p>In stock: {inStockProducts.length}</p>
      <p>Total: ${totalPrice}</p>
    </div>
  );
};

// ❌ Bad - Don't store what can be calculated
const ProductList = ({ products }: { products: Product[] }) => {
  const [totalPrice, setTotalPrice] = useState(0);
  
  useEffect(() => {
    setTotalPrice(products.reduce((sum, p) => sum + p.price, 0));
  }, [products]); // Redundant useEffect and state!
};
```

### useEffect

```typescript
// ✅ Good - Correct dependencies
useEffect(() => {
  fetchUser(userId);
}, [userId]);

// ✅ Good - Cleanup function
useEffect(() => {
  const timer = setInterval(() => console.log('tick'), 1000);
  return () => clearInterval(timer);
}, []);

// ✅ Good - Separate effects for separate concerns
useEffect(() => { /* Logic A */ }, [depA]);
useEffect(() => { /* Logic B */ }, [depB]);

// ❌ Bad - Missing dependencies or too many concerns in one effect
```

### useMemo and useCallback

Use these only for:
- ✅ Expensive calculations (filtering/sorting large arrays).
- ✅ Maintaining stable references for dependencies of other hooks.
- ✅ Passing props to `React.memo` components.

```typescript
// ✅ Good - Stable function reference
const handleSearch = useCallback((value: string) => {
  console.log('Searching:', value);
}, []);

// ❌ Bad - Premature optimization
const name = useMemo(() => user.name, [user]); // Overkill!
```

## Components Strategy

### Props and Children

```typescript
interface CardProps {
  title: string;
  children: React.ReactNode;
}

// ✅ Good - Typed props and children
export const Card = ({ title, children }: CardProps): JSX.Element => (
  <div className="card">
    <h2>{title}</h2>
    <div className="card-content">{children}</div>
  </div>
);
```

### Lists and Keys

```typescript
// ✅ Good - Unique stable key
{products.map(product => (
  <ProductCard key={product.id} product={product} />
))}

// ❌ Bad - Missing key or using index in dynamic lists
```

### Conditional Rendering

```typescript
// ✅ Good - Simple conditions
{isLoading && <Spinner />}
{user ? <UserProfile user={user} /> : <LoginForm />}

// ✅ Good - Early return for complex conditions
const UserProfile = ({ user }: { user: User | null }) => {
  if (!user) return <div>Please login</div>;
  
  return <h1>{user.name}</h1>;
};
```

## Performance & Optimization

### React.memo

Use only when props change infrequently and the component is heavy.

```typescript
export const ProductCard = React.memo(({ product, onAddToCart }: Props) => {
  return <div onClick={() => onAddToCart(product.id)}>{product.name}</div>;
});
```

### Lazy Loading

```typescript
const ProductPage = lazy(() => import('./pages/ProductPage'));

const App = () => (
  <Suspense fallback={<Loading />}>
    <Routes>
       <Route path="/products" element={<ProductPage />} />
    </Routes>
  </Suspense>
);
```

## Accessibility (a11y)

```typescript
// ✅ Good - Semantic HTML + ARIA
const Modal = ({ isOpen, title, children }: Props) => (
  <div role="dialog" aria-modal="true" aria-labelledby="modal-title">
    <h2 id="modal-title">{title}</h2>
    {children}
  </div>
);
```

## Restrictions (What NOT to do)

❌ **NO `function` keyword**: Strictly use `const Component = () => {}`.  
❌ **NO State Mutation**: Use functional updates and spread operators.  
❌ **NO Over-effecting**: Don't use `useEffect` if logic can be handled in events or during render.  
❌ **NO Inline Styles**: Always use **Tailwind CSS** classes.  
❌ **NO index as key**: Use unique IDs for list items.  

## Pre-commit Checklist

- [ ] All components and hooks use **Arrow Function** syntax.
- [ ] Props are defined using an `interface`.
- [ ] List items have unique and stable `key` props.
- [ ] No direct state mutations.
- [ ] No redundant `useEffect` for derived state.
- [ ] Accessibility (semantic HTML and ARIA labels) is maintained.
- [ ] No `console.log` in the final code.
